# Cradle Built-ins (Stage 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, inline, in this session. Two repositories, a live NAS, a KVM test VM and a pre-stage-2 render baseline are context a fresh subagent would not have. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Traefik and the kopia server stop being service folders a host repository carries and become **built-ins**: folders Cradle ships and places itself. The host says in one `backup:` block whether it backs up, where the repository lives and where the replica goes; the two built-ins' credentials move into the host's secrets; the kopia client passwords are generated on the host and written by nobody; `hosts/shared/` goes.

**Architecture:** A built-in is a service folder under `cradle/ansible/builtins/<name>/`, placed by the playbook before the host's own folders — traefik always, kopia wherever `backup` is a block. The `service` role sees an ordinary service: it gets the spec, the folder and, as two include params, the things only the playbook knows — `secrets_file_override` (the host's `ingress.sops.yaml` / `backup.sops.yaml`) and `generated_secrets` (a podman secret name to a file on the host that `host_base` filled with 32 random bytes). The host's `backup.repository` arrives as the `kopia/repo` volume override, `backup.domain`/`ingress.domain` as the route label, `backup.username` and `backup.replica.*` as play vars the kopia template reads directly.

**Tech Stack:** Ansible (ansible-core 2.21), Podman Quadlet, Molecule + testinfra in a KVM VM, pytest, sops/age, mise, Docker devtools image, GitHub Actions, `gh`.

**Spec:** `docs/superpowers/specs/2026-10-17-cradle-built-ins-design.md` (this repository; copied into Cradle in Task 4). Stage 1's spec and plan are `2026-10-16-cradle-split-design.md` / `2026-10-16-cradle-split.md`.

- [ ] **Step 3: kopia's spec loses the config block and the client list**

`ansible/builtins/kopia/service.yml` becomes, in full:

```yaml
name: kopia
port: 51515
# The default route label. The host overrides it with `backup.domain`, which the playbook
# applies onto this spec before the role sees it -- the one host-owned fact in a
# built-in's contract (docs/ownership.md § 1.1: a host fact arrives from host.yml).
domain: kopia
# The server speaks TLS itself, because its repository protocol is gRPC and gRPC is
# HTTP/2 -- Traefik reaches an HTTP/2 backend only over TLS. The certificate it
# re-encrypts to is the self-signed one the server makes for itself on first start, so
# there is nothing to verify it against; the hop is to 127.0.0.1. See the README.
route:
  scheme: https
  insecure_skip_verify: true
volumes:
  config: { class: pool }
  cache: { class: fast }
  logs: { class: fast }
  # The repository itself, and the reason this is `pool` and not `fast`: it is the
  # primary copy of every backup on this host. Its path is the host's choice --
  # `backup.repository` in host.yml, which the playbook applies as this volume's
  # override -- and `owner: 0` is the uid kopia runs as inside the container, which is
  # the service user. It is declared because the role only adopts an *existing*
  # directory's owner when `owner` is, and this is a path an operator plausibly creates
  # by hand: a root-owned directory left unadopted converges green and leaves kopia
  # unable to write to its own repository, restart-looping where nobody is looking.
  repo: { class: pool, owner: 0 }
# The host's, from `hosts/<name>/secrets/backup.sops.yaml`: the playbook hands the role
# that path. The client passwords are not here -- they are generated on the host, one
# per backed-up service, and synced in by the role (spec 2026-10-17 § 4).
secrets: [server_password, repository_password, b2_key_id, b2_application_key]
backup: none
```

```python
def _builtins(host: str) -> list[tuple[str, Path, dict, None]]:
    """Every built-in placed on a host, with the host's route label applied.

    The label is the one host-owned fact inside a built-in's spec, so it is applied here
    exactly as the playbook applies it before the role sees the spec -- otherwise a host
    that renamed its dashboard would make every route assertion in this suite look for a
    file the render does not write.
    """
    cfg = load_yaml(HOSTS / host / "host.yml")
    out = []
    for name in sorted(p.name for p in BUILTINS.iterdir() if p.is_dir()):
        if name == "kopia" and cfg.get("backup", "none") == "none":
            continue
        spec = load_yaml(BUILTINS / name / "service.yml")
        label = (
            cfg.get("ingress", {}).get("domain")
            if name == "traefik"
            else cfg["backup"].get("domain")
        )
        out.append((name, (BUILTINS / name).resolve(), {**spec, "domain": label} if label else spec, None))
    return out


def placements() -> list[Placement]:
    result = []
    for host in host_names():
        for name, dir_, spec, pointer in _builtins(host) + _services_in(HOSTS / host / "services"):
            result.append(Placement(host, name, dir_, spec, pointer))
    return result
```

```yaml
# One generated password per backed-up service, and the whole of what makes a client
# password nobody's to write: created on the first converge that places the service,
# never rewritten, never in git, and the only two readers are the role tasks that sync it
# into the consumer's `kopia_password` and the server's `client_<svc>`. A fresh host
# re-registers its clients with new values; the *repository* password stays the
# operator's, in the host's backup.sops.yaml. spec 2026-10-17 § 4.
#
# This runs in host_base, which the playbook runs before any service, so the file exists
# by the time the first consumer's secrets are synced.
- name: The backup clients' directory
  ansible.builtin.file:
    path: '{{ backup_clients_dir }}'
    state: directory
    owner: root
    group: root
    mode: '0700'
  when: backup != 'none'

# `creates:` and not a `when:` over a stat: the guard belongs on the task that writes, so
# a second converge reports no change and a `--check` run says what a first one would do.
# `tr -d` because `openssl rand -base64` ends its output with a newline, and the value
# goes into an env-type podman secret the sidecar reads as KOPIA_PASSWORD -- a trailing
# newline there is a password that does not match the server's.
- name: One generated password per backed-up service, created once and never rewritten
  ansible.builtin.command:
    cmd: /bin/sh -c "umask 077; openssl rand -base64 24 | tr -d '\n' > {{ backup_clients_dir }}/{{ item }}"
    creates: '{{ backup_clients_dir }}/{{ item }}'
  loop: '{{ backup_clients | default([]) }}'

- name: Look for the generated passwords
  ansible.builtin.stat:
    path: '{{ backup_clients_dir }}/{{ item }}'
  loop: '{{ backup_clients | default([]) }}'
  register: _client_password_files

# The umask above already gives a new file 0600; this holds it there for one an older
# converge or an operator left readable. Guarded the way host_base's default certificate
# is: the task that creates the file carries `creates:` and is skipped under `--check`,
# and `file` without a `state:` refuses an absent path.
- name: The generated passwords are root-only
  ansible.builtin.file:
    path: '{{ item.stat.path }}'
    owner: root
    group: root
    mode: '0600'
  loop: '{{ _client_password_files.results }}'
  loop_control:
    label: '{{ item.item }}'
  when: item.stat.exists
```
